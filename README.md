# ずんだもん・四国めたん 解説動画ジェネレーター

画像・読み上げテキスト・表示秒数を入力するだけで、ずんだもん / 四国めたんの
合成音声付き解説動画を自動生成するStreamlitアプリです。

## セットアップ

```bash
python -m venv .venv
source .venv/bin/activate  # Windowsは .venv\Scripts\activate
pip install -r requirements.txt

# 動作確認用のダミー立ち絵素材を生成（初回のみ。実素材に差し替える場合は不要）
python scripts/generate_placeholder_assets.py

streamlit run app.py
```

動画を生成するには、**別途 [VOICEVOX](https://voicevox.hiroshiba.jp/) を起動しておく必要があります**
（デフォルトで `http://localhost:50021` にHTTPサーバーが立ち上がります）。
VOICEVOXを起動せずに「🚀 動画を生成する」を押した場合は、アプリがクラッシュする代わりに
「VOICEVOXが起動していません。VOICEVOXを起動してから再度実行してください。」という
警告がUI上に表示されます。

ffmpegは `imageio-ffmpeg` パッケージが自動的に用意するため、別途インストールする必要はありません。

## 話者ID（VOICEVOXのキャラクター）の設定

`src/services/voicevox_client.py` の `VOICEVOX_SPEAKER_IDS` に定数として定義しています。

```python
VOICEVOX_SPEAKER_IDS = {
    "zundamon": 3,        # ずんだもん（ノーマル）
    "shikoku_metan": 2,   # 四国めたん（ノーマル）
}
```

「あまあま」「ツンツン」等の別スタイルを使いたい場合は、VOICEVOXを起動した状態で
`http://localhost:50021/docs` を開き `/speakers` の応答からスタイルIDを確認し、
この辞書の値を書き換えてください（`voicevox_client.list_available_speakers()` を
Pythonから直接呼び出しても一覧を取得できます）。

## リップシンクのしきい値調整

`src/services/lipsync.py` の `DEFAULT_VOLUME_THRESHOLD`（既定値 `0.02`）で調整できます。
声が小さいと感じる場合は値を下げ、環境音やノイズで口が開きっぱなしになる場合は値を上げてください。

## 2人実況レイアウト

画面には常に**左側にずんだもん・右側に四国めたん**が表示されます。シーンで選んだ「話者」だけが
選択した表情でリップシンク（口パク）し、話していない方はそのキャラクターの既定表情
（`config/characters.json` の `default_expression`、既定値 `"normal"`）で口を閉じた待機状態になります。
待機中の表情を変えたい場合はこの値を書き換えてください。

## テロップの色分け・視認性・改行

テロップの文字色・縁取り色は話者に応じて `config/characters.json` の `telop` で切り替わります。

```json
"telop": { "color": "#4CAF3D", "stroke_color": "#FFFFFF" }
```

既定はずんだもん＝緑地に白フチ、四国めたん＝ピンク地に黒フチです。色を変更したい場合はここの
`color` / `stroke_color` を書き換えてください。

テロップの描画は `src/services/telop.py` がPillowで行っており（MoviePyの `TextClip` は使用していません）、
文字の背後に半透明の黒い背景ボックスを敷くことで、背景画像が明るい場合でも文字が読みやすくなるように
しています。背景ボックスの色・透明度は `telop.py` の `TELOP_BG_COLOR`（既定 `(0, 0, 0, 150)`。
4つ目の数値が不透明度で0〜255）で調整できます。

### 改行について

読み上げテキストの入力欄（シーン編集画面）で **Enterキーを押すとその位置で改行**され、テロップにも
そのまま反映されます。改行しなかった場合でも、1行が画面幅に収まらないときはPillowでのフォント幅の
実測に基づき自動的に折り返されます（日本語のようにスペースを含まない文章でも正しく折り返されます）。

1行あたりの文字数の目安（既定のフォントサイズ設定の場合）は以下の通りで、シーン編集画面の
読み上げテキスト入力欄のヘルプ（「?」アイコン）にも同じ目安が表示されます。狙った位置で改行したい
場合は、この目安を超えたあたりでEnterを押してください。

| フォーマット | 解像度 | 1行の目安文字数 |
| --- | --- | --- |
| 横画面 | 1920x1080 | 約30文字 |
| 縦画面 | 1080x1920 | 約17文字 |

（この目安は `telop.recommended_chars_per_line()` が実際のフォントを使って計算しているため、
フォントを差し替えた場合は多少前後します。）

## 表示秒数（強制カット）と話速の自動調整

各シーンの「表示秒数」は**絶対値**として扱われます。

1. まず `/audio_query` のmora単位の長さ情報から、音声を実際に生成せずに「等速(speedScale=1.0)なら
   何秒かかるか」を見積もります。
2. それが表示秒数を超える場合、指定秒数にちょうど収まるよう `speedScale` を自動的に引き上げてから
   音声を合成します（既定の上限 `MAX_SPEED_SCALE = 2.0`。`src/services/voicevox_client.py` で変更可能）。
3. それでも上限速度で収まりきらない場合は、話速はその上限に留めたうえで、従来通り表示秒数で
   映像・音声を強制的にトリミングします。
4. 逆に音声がそれより短い場合（話速調整が不要なケース） → 背景・立ち絵は表示秒数いっぱいまで
   維持され、残り時間は無音で埋められます。

生成後、話速が自動調整されたシーンや、上限を超えて強制カットが発生したシーンについては、
「⚠️ 生成時の注意事項」としてUI上にまとめて表示されます。

## 素材（アセット）の差し替えについて

このアプリは「福笑い方式」（体・目・口をパーツごとに重ねて合成する方式）は採用していません。
表情・口の開閉の組み合わせごとに、**あらかじめ合成し終えた1枚の完成画像**を用意する方式です。

各PSD（`ずんだもん立ち絵素材2.3.psd` / `四国めたん立ち絵素材2.1.psd`）から、表情ごとに
「口を開けた状態」「口を閉じた状態」をそれぞれ1枚の画像として書き出し、
`assets/zundamon/` および `assets/shikoku_metan/` に以下の命名規則で配置してください。

- `[表情名]_open.png` … その表情で口を開けている状態（1枚の完成絵・透過PNG）
- `[表情名]_close.png` … その表情で口を閉じている状態（1枚の完成絵・透過PNG）

例: `normal_open.png` / `normal_close.png`、`happy_open.png` / `happy_close.png` など。
**`_open.png` と `_close.png` が両方そろっている表情だけ**がUIの表情選択肢に表示されます
（`asset_loader._scan_expression_pairs` / `has_expression_assets`）。表情を追加したい場合は、
このopen/closeのペアを追加で書き出して配置するだけで、UIの表情選択肢に自動反映されます。
なお、口パクのアニメーションでは同じキャラクター・同じ表情の`_open.png`と`_close.png`を
交互に差し替えるだけなので、2枚の顔・体の位置や大きさがずれないよう、同一キャンバスサイズで
書き出してください。

動作確認用に、図形描画で作ったダミー素材（`scripts/generate_placeholder_assets.py`）を
同梱しています。実素材に差し替える場合は、同じファイル名規則で
`assets/zundamon/`・`assets/shikoku_metan/` 配下のファイルを置き換えてください
（ダミー素材を再生成したい場合は同スクリプトを再実行すると、旧方式のファイル
（`base.png`・`mouth_open.png`・`mouth_close.png`・`eyes_*.png`）が残っていても自動的に削除されます）。

表情キーとその日本語表示名は `config/characters.json` の `expressions` で管理しています。
ファイルを配置しただけでも表情としては認識されますが、ラベルを日本語にしたい場合は
このJSONにキーを追記してください。

## テロップ用フォントについて

`assets/fonts/NotoSansJP-Regular.otf` は Google の Noto Sans CJK JP から日本語表示に
必要な範囲を抽出したサブセットで、SIL Open Font License 1.1（`OFL-1.1-NotoSansCJK.txt`）
のもとで同梱しています。別のフォントを使いたい場合は、このファイルを差し替えるか、
`src/services/telop.py` の `FONT_PATH` を書き換えてください。

## BGM（背景音楽）について

サイドバーの「🎵 BGM（背景音楽）」から、mp3 / wav / m4a ファイルをアップロードできます。

- BGMが動画より短い場合は自動的にループ再生され、長い場合は先頭から動画の長さぶんだけ
  トリミングされます。
- ナレーションの邪魔にならないよう、音量スライダー（既定値0.25）でBGM音量を調整できます。
- 不自然な音の始まり/切れ方を避けるため、頭とお尻に短いフェードイン/フェードアウトが
  自動的に入ります。
- BGMファイルが見つからない・壊れている等の場合でもアプリはクラッシュせず、
  「BGMなしで書き出しました」という警告とともに動画自体は生成されます。

## プロジェクトの保存・読み込み

サイドバーの「💾 プロジェクトの保存・読み込み」から、作業内容（プロジェクト名・フォーマット・
シーン一覧・BGM設定）をJSONファイルとして保存し、あとで読み込んで続きから編集できます。
アップロードした背景画像・BGMファイル自体は `assets/` 配下に保存されているため、
それらのファイルごと（プロジェクトフォルダ全体を）保管しておくと確実です。

「📂 このプロジェクトを読み込む」を押すと、現在編集中の内容は読み込んだ内容で上書きされます
（保存し忘れた変更がある場合はご注意ください）。壊れたファイルを読み込もうとした場合は、
アプリを落とさずエラーメッセージを表示します。

## 台本からのシーン一括生成

シーン編集画面の「📄 台本から一括でシーンを作成」から、複数行の台本テキスト（貼り付け、または
.txtファイルのアップロード）をもとに、複数シーンをまとめて生成できます。

- 行頭に `ずんだもん: ◯◯` / `四国めたん: ◯◯`（半角コロン`:`でも可）と書くとその話者に
  切り替わります。話者名を書かない行は、**指定があるまで直前の話者がそのまま続けて
  話す**扱いになります（自動で相手のキャラに交互切り替えすることはありません）。
  2人の掛け合い台本にしたい場合は、話者が変わる行にだけ `話者名:` を書いてください。
- **話者・表情が直前の行と同じ行は、新しいシーンにはならず、直前のシーンの読み上げ
  テキストに改行で連結されます**（シーン編集画面で手動でEnterキーを押して改行するのと
  同じ扱いです）。話者または表情が変わったときだけ新しいシーンになります。台本を
  読みやすくするために入れた改行が、意図せず別カット（別シーン＝別々の音声合成・
  ハードカット）として切り出されてしまうのを防ぐためのものです。
- 話者名は表示名（`ずんだもん` / `四国めたん`）・内部キー（`zundamon` / `shikoku_metan`）に加えて、
  `config/characters.json` の各キャラクターの `"aliases"` に登録したニックネームでも指定できます
  （既定では `めたん` → 四国めたん、`ずんだ` → ずんだもん）。よく使う略称があれば `aliases` に
  追加しておくと、その略称でも認識されるようになります。
  `話者名(表情):` の書き方をしていて話者名（カッコの前の部分）が認識できなかった場合は、
  エラーにはせず話者名部分だけを読み上げテキストから取り除いたうえで、直前の話者のまま
  処理を続け、その旨を生成後に警告としてお知らせします（話者名がそのまま声で読み上げ
  られてしまう事故を防ぐため）。
- 話者名の直後に括弧で表情も指定できます（例: `ずんだもん(喜び): ◯◯`、半角`()`/全角`（）`
  どちらも可。開き括弧・閉じ括弧で半角/全角が混ざっていても認識できます）。表情名は
  `config/characters.json` の日本語ラベル（例: `喜び`）でも、内部キー（例: `happy`）でも
  指定できます。表情指定を省略した行は、その話者の既定表情（`default_expression`）に
  なります。見つからない表情名を指定した場合はエラーにはせず、既定表情にフォールバック
  したうえで、その旨を生成後にお知らせします。
- 各シーンの表示秒数は、既存の目安ロジック（`estimate_duration`）から自動算出されます。
- 各シーンの背景は、直前の最後のシーンと同じ背景（画像/動画）が自動的に引き継がれます。
- 「既存のシーンを置き換える」をオフのままにすると、生成したシーンは末尾に追加されます
  （オンにすると既存のシーンを全て置き換えます）。

## 背景に動画ファイルを使う

各シーンの「背景画像/動画をアップロード」から、mp4 / mov / webm / m4v 形式の動画ファイルも
背景として指定できます（`src/services/background_video.py`）。

- 動画がシーンの表示秒数より短い場合は自動でループ再生され、長い場合は先頭から表示秒数ぶん
  だけトリミングされます（`MoviePy` の `vfx.Loop` エフェクトを使用）。
- 動画自体の音声は常に無視されます（VOICEVOXのナレーション・BGMと混ざらないように）。
- 画像背景と違い、動画背景は1フレームごとに背景動画のコマを取り出して立ち絵と合成し直す必要が
  あるため、画像背景（「口:開」「口:閉」の2枚だけを使い回す軽量な方式）に比べて動画の生成に
  時間がかかります。長いシーンで動画背景を多用する場合は書き出し時間にご注意ください。
- シーン編集画面のプレビューでは、動画の代表的な1コマ（先頭付近のフレーム）を静止画として
  表示します（実際の動画生成時は、その時刻ごとのコマがちゃんと使われます）。
- 動画の読み込みに失敗した場合（壊れたファイル・非対応コーデック等）でもアプリは落ちず、
  単色の背景にフォールバックしたうえで警告付きで動画自体は生成されます。

## 共通の背景画像/動画

サイドバーの「🖼 共通の背景画像」から、全シーンで共通して使う背景（画像/動画）を1つ
設定できます。各シーンの「背景画像」を個別に設定していないシーンだけ、この共通背景が
自動的に使われます（＝シーンごとに背景を上書き指定した場合は、そちらが優先されます）。

- 例えば「動画全体で同じ枠・装飾画像を敷いておき、資料や写真を出したいシーンだけ
  個別の背景に差し替える」といった使い方ができます。
- 共通背景も動画ファイルに対応しており、シーンの背景と同様に表示秒数へ合わせて
  自動でループ／トリミングされます。
- 「🗑 共通の背景を削除」でいつでも解除できます。

## 資料メディア（写真/動画を画面中央に表示）

各シーンの「資料メディア（写真/動画・画面中央に表示）」から、背景とは別のレイヤーとして、
スクリーンショットや資料写真・資料動画などを画面の上部〜中央に大きく見やすく配置できます。

- 背景（画面全体を覆うカバーフィット）とは異なり、資料メディアはアスペクト比を保ったまま
  画面に収まるサイズ（containフィット）で中央に配置され、下端の2人の立ち絵やテロップと
  重ならないようになっています。
- 合成順序は「背景 → 資料メディア → 立ち絵」の順で、資料メディアは背景の上・立ち絵の下に
  重なります。
- 動画ファイルにも対応しており、背景動画と同様に表示秒数へ合わせて自動でループ／
  トリミングされ、音声は常にミュートされます。
- 資料メディアは任意項目です。未設定のシーンではこれまで通り、背景+立ち絵だけの画面になります。
- 背景・資料メディアのどちらか一方でも動画ファイルの場合、そのシーンは1フレームずつ
  合成し直す方式になるため（画像だけの場合の「口:開」「口:閉」2枚を使い回す軽量化が
  使えないため）、動画の生成にやや時間がかかります。

## ビフォーアフター画像（2枚を左右分割で同時表示）

美容・コスメ系のレビュー動画などで定番の「使用前/使用後」比較を、写真2枚を指定するだけで
自動レイアウトできます。各シーンの「📸 ビフォーアフター画像」からBefore画像・After画像を
それぞれ選択（またはアップロード）してください。

- Before/After の**両方**が設定されている場合のみ有効になり、画面を左右分割してcontain
  フィットで同時表示し、それぞれに「BEFORE」「AFTER」のラベルバッジを重ねます。
  片方だけ設定されている場合や、通常の資料メディアと同時に設定した場合は、
  ビフォーアフター表示が優先されます（資料メディアは表示されません）。
- 静止画のみ対応です（動画ファイルは選択肢に出てきません）。
- 保存先は資料メディアと同じ `assets/content_media/` フォルダです。

## PR/広告表記バッジ（ステマ規制対応）

サイドバーの「📢 PR/広告表記」から、動画全体に常時表示するPR/広告表記バッジのON/OFFと
表示文言を設定できます。アフィリエイト・PR案件の動画で、広告であることを明示する目的の
機能です。

- ONにすると、画面右上に半透明の赤いバッジとして動画の最初から最後まで常時表示されます
  （2023年10月施行のステマ規制で、表示が動画の冒頭だけ・見落としやすい位置だけだと不十分と
  されているため、常時表示にしてあります）。
- 表示文言は自由に変更できます（例:「PR」「広告」「〇〇社から商品提供を受けています」など）。
- プロジェクト全体で一括のON/OFFのみで、シーンごとの個別設定はできません。
- ⚠️ この機能はあくまで表示を補助するものであり、実際にどのような表記が必要かは
  景品表示法・各プラットフォームの規約によります。最終的な表記内容・要否はご自身で
  ご確認ください（[消費者庁 ステマ規制Q&A](https://www.caa.go.jp/policies/policy/representation/fair_labeling/faq/stealth_marketing/)）。

## シーンごとの音声プレビュー

各シーンの「🔊 音声を試聴」ボタンから、動画全体を書き出す前にそのシーンの声（VOICEVOX）だけを
その場で聞くことができます。表示秒数に収めるための話速自動調整も、実際の動画生成時と同じ条件で
適用されます。VOICEVOXが起動していない場合は、動画生成時と同じ「VOICEVOXが起動していません…」
という警告が表示されます。

## 読み方辞書（誤読の修正）

VOICEVOXは内部の辞書に基づいてテキストを自動で読み上げますが、「人」を「じん」と読んでしまう
など、文脈によっては誤読することがあります。サイドバーの「🗣 読み方辞書（誤読の修正）」から、
「単語」と「読み（ひらがな/カタカナ）」のペアを登録すると、テロップの表示テキストはそのままに、
VOICEVOXへ渡す読み上げテキストの中だけをその読みに置き換えます（音声プレビュー・動画生成の
両方に適用されます）。

登録した単語は単純な文字列置換で処理されます。「人」のように1文字だけ、かつ読み方が文脈で
変わりうる単語を登録すると、「日本人」「友人」のように別の単語の一部まで意図せず置き換わって
しまうことがあるため、実際に誤読された単語・フレーズ単位（例:「二人」→「ふたり」、
「一人暮らし」→「ひとりぐらし」）で登録することをおすすめします。

## 動画の生成を速くする

動画生成画面に「書き出し速度」の選択肢があります（既定は「⚖️ バランス」）。

| 選択肢 | 内容 |
| --- | --- |
| ⚡ 高速優先 | 一番速く書き出せます（ファイルサイズは大きめ）。内容確認用の下書きにおすすめです。 |
| ⚖️ バランス（既定） | 体感速度と画質・ファイルサイズのバランスを取った設定です。 |
| 🎬 高画質優先 | 一番時間がかかりますが、同じファイルサイズならより高画質になります。SNS公開用の最終版などに。 |

内部的にはffmpeg(libx264)の`preset`を切り替えており（`src/services/video_builder.py`の
`ENCODE_PRESETS`）、あわせてマルチスレッドでのエンコードも有効にしています。

これは「MP4への書き出し(エンコード)」自体の速度を変えるものなので、それ以外で生成時間に
大きく影響するポイントとしては、次のようなものがあります。

- **背景に動画ファイル・資料メディアに動画ファイルを使っているシーンが多いほど遅くなります。**
  画像だけのシーンは「口:開」「口:閉」の2枚の完成フレームを使い回す軽量な方式で処理されますが、
  背景または資料メディアのどちらかが動画ファイルのシーンは、1フレームずつ合成し直す必要が
  あるため、同じ長さでも画像だけのシーンよりずっと時間がかかります。動画確認を素早く
  繰り返したい場合は、一旦画像素材で組んでみて、最後の仕上げだけ動画素材に差し替える、
  といった進め方がおすすめです。
- シーン数・動画全体の長さが長いほど、VOICEVOXでの音声合成・リップシンク解析・フレーム
  合成・エンコードのすべてに比例して時間がかかります。
- VOICEVOX自体の音声合成速度は、お使いのPCのCPU/GPU性能に依存します（このアプリ側からは
  調整できません）。

## シーンの切り替わりでの一瞬の暗転対策

背景・立ち絵ががらっと変わるシーンの切り替わり（ハードカット）を、Bフレーム
（前後のフレームを参照しながら圧縮するフレーム）をまたいでエンコードすると、
一部の再生環境でカットの瞬間だけ画面が一瞬暗転して見えることがあります。
これを防ぐため、各シーンの切り替わり位置に強制的にキーフレームを挿入し
（`-force_key_frames`）、Bフレーム自体も無効化して（`-bf 0`）書き出すようにしています
（`src/services/video_builder.py` の `_build_scene_cut_ffmpeg_params`）。

## 【重要】テロップ（字幕）が切り替わらず前のシーンのまま残る場合

MoviePy 2.1.2 未満には、透過画像（テロップ）を重ねたCompositeVideoClip同士を
`concatenate_videoclips()` で連結すると合成がおかしくなり、シーンが切り替わっても
テロップだけ前のシーンの内容のまま表示され続けてしまう既知の不具合があります。
本アプリはシーンごとに「立ち絵+背景の動画」に「テロップ画像」をCompositeVideoClipで
重ねてから、それを全シーン分連結する構成のため、まさにこの不具合の影響を受けます。

対策として、`requirements.txt` で `moviepy>=2.1.2` を必須にし、さらに
`concatenate_videoclips()` の呼び出しでも `method="compose"`（既定の`"chain"`ではなく）
を明示的に指定することで、この不具合を回避しています
（`src/services/video_builder.py` の `build_video()` 内、シーン結合部分）。

既にインストール済みの環境でこの症状が起きた場合は、以下でMoviePyを更新してから
再度動画を生成してください。

```bash
pip install -r requirements.txt --upgrade
```

## 本から台本を自動生成（Claude API）

書籍解説モードの「🤖 本から台本を自動生成（Claude）」で、本のテキスト（.txt / .pdf）から
ずんだもんと四国めたんの掛け合い台本を自動で作れます（`src/services/book_ai.py`）。

1. `.env.example` をコピーして `.env` を作り、`# === Anthropic ===` の下の `ANTHROPIC_API_KEY=` に
   Claude APIのキーを書いてアプリを再起動します（`.env` はGitにコミットされません）。
   使うモデルは `ANTHROPIC_MODEL`（既定: `claude-opus-5`）で変更できます。
2. 本のファイルをアップロードし、「① 本を分析する」で章ごとの要点・悩み・テーマを抽出します
   （「📏 費用を見積もる」で事前に入力トークン数と費用の目安を確認できます）。
3. 分析結果を確認・修正し、「② 台本を生成する」で台本JSONを作ってそのままシーンに反映します。

APIを使わない「手動」モードでは、Claudeのチャット画面（claude.ai）に貼り付けるプロンプトを表示します。
## 既知の制限・今後の改善候補

- 各シーンで喋る（リップシンクする）のは1人までです。ずんだもん・四国めたんは常に両方
  画面に表示されますが、掛け合い（1シーン内で交互に喋らせる）には未対応です
  （台本の一括読み込み機能を使えば、行ごとに話者が交互に切り替わる複数シーンとして
  実質的な掛け合いを作れます）。
- 立ち絵の左右位置・サイズは `src/services/compositor.py` の `DUAL_CHARACTER_*` 定数で調整できます。
- 長い動画（シーン数・秒数が多い場合）はPillowでのフレーム合成とMoviePyのエンコードに
  一定の時間がかかります。処理中は進捗メッセージが表示されますが、そのままお待ちください。
